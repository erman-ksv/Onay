# Onay — отчёт по пункту 8.11 и полный чек-лист

15.10.2026. Задача начата 14.10.2026. Исходная база: main после PR #36, cf1a38c0a499264579e0a39de5716cf2b3cf974a. Отдельная ветка feat/api-safe-errors-20261014. PR #37 с OTP открыт и не включён в эту ветку.

## Результат этапа

8.11 «Безопасная обработка ошибок API» реализован и проходит обязательные проверки CI. До окончательной приёмки и объединения пункт остаётся открытым.

Перед изменениями выполнены два независимых глубоких аудита HTTP, Socket.IO, startup, фоновых задач, сервиса адресов, PostgreSQL, логгера и тестов. Найдены утечки текста upstream-ошибки клиенту, SQL/параметров и URL в журналы; неправильный 500 для parser errors; отсутствие JSON404 и headersSent guard; необработанные startup rejections.

Что изменено:

- Единые публичные JSON-ошибки с сохранением прежних business 4xx. Внутренние 5xx имеют фиксированный текст, без SQL/параметров/stack/cause.
- Правильные 400/413/415 для известных ошибок тела и пути; неизвестный endpoint возвращает JSON404. Неизвестные объекты с произвольным status не считаются публичными ошибками.
- Известные конфликты PostgreSQL дают контролируемый 409, известные ошибки подключения — 503; остальные внутренние SQL-сбои — 500.
- Серверный UUID в X-Request-Id и request_id связывает ответ с журналом. Входные ID не используются.
- Общий сериализатор журналов исключает исходные сообщения, стеки, причины, SQL, параметры, тела и произвольные поля. HTTP журнал сохраняет шаблон маршрута, не URL, query или личные сегменты пути. То же действует для Socket.IO, dispatch и запуска сервера.
- После headersSent нет повторной записи ответа; стандартному Express handler передаётся очищенная ошибка.
- Ошибка инициализации безопасно записывается, сервер завершается с ненулевым кодом. Тело ошибки Gemini не читается и не отражается клиенту. Существующие коды 502/503/504 сохранены.

## Проверки

Локально прошли native Node проверки публичных ошибок, allowlist сериализации, parser/SQL mapping, недоверенных полей, getters/циклов/Proxy, серверных UUID, шаблонов маршрутов и ошибок провайдера. Синтаксис нового теста и git diff --check чистые.

Независимое ревью обнаружило регрессию timeout чтения provider body; исправлено сохранение 504/GEMINI_TIMEOUT. Неверный null/array envelope теперь правильно классифицируется как 502/GEMINI_INVALID_RESPONSE.

Добавлен api-errors.test.mjs: 14 смысловых сценариев, настоящий production app, JSON-логгер, PostgreSQL и Socket.IO. Ошибки SQL создаются в отдельной схеме, захватываются настоящие stdout/stderr. Проверяются маркеры SQL, параметров, токенов, OTP, адреса, query и пути; HTTP статусы и восстановление после сбоя; headersSent; startup exit; upstream failures и timeout чтения body. Проверки внешнего провайдера используют тестовый fetch, не реальный Gemini.

Полный TypeScript, миграции, API suite и браузерные регрессии должны пройти CI для окончательного HEAD. До зелёных результатов завершение не подтверждается; ссылки и окончательные результаты фиксируются в PR и итоговом отчёте пользователю.
